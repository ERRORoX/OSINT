## Краткий вывод

Архитектурная основа пригодна для поэтапной модернизации, но текущую конфигурацию нельзя считать безопасной для публикации в интернете или недоверенной локальной сети. Самый важный блокер — чувствительные API-маршруты не имеют видимого механизма аутентификации/авторизации, при этом приложение по умолчанию слушает все сетевые интерфейсы и запускает Flask с debug.

## Находки

### CRITICAL — чувствительные API доступны без видимой аутентификации

**Файлы:** `backend/app.py` (маршруты API примерно строки 819–1490).

В проверенных обработчиках не обнаружены декораторы или middleware авторизации. В частности, доступны:
- запуск зарегистрированного инструмента: `POST /api/tools/<tool_id>/run`;
- чтение, удаление и очистка истории: `/api/history`;
- чтение и изменение настроек API-ключей: `/api/settings/keys`;
- чтение и экспорт файлов/медиа GrabCam;
- чтение захваченных данных FormGrab;
- управление состоянием и настройками модулей.

**Риск:** любой пользователь, который может обратиться к серверу, потенциально может запускать инструменты, менять настройки, читать результаты и получать сохранённые данные. CORS не заменяет аутентификацию и не является контролем доступа.

**Исправление:** закрыть чувствительные API по умолчанию; добавить серверную аутентификацию, проверку ролей/прав на каждый маршрут, CSRF-защиту для cookie-сессий и безопасную политику CORS. Медиа, история, настройки и административные действия должны быть доступны только авторизованному владельцу/оператору.

### CRITICAL — публичный сетевой bind и debug-режим

**Файлы:** `run.py`, `backend/app.py`.

Оба запуска вызывают `app.run(host="0.0.0.0", ..., debug=True)`.

**Риск:** сервис слушает все интерфейсы; debug-режим не предназначен для production и может раскрывать внутреннюю информацию при ошибках. В сочетании с открытыми API это существенно увеличивает последствия сетевого доступа.

**Исправление:** debug выключен по умолчанию; использовать production WSGI-сервер. По умолчанию слушать loopback. LAN-доступ включать отдельной явной настройкой и только вместе с авторизацией. Не выставлять development server в интернет.

### CRITICAL — модули захвата учётных данных и перебора паролей

**Файлы:** `backend/tools/tool_formgrab.py`, `backend/tools/tool_instagram_bruter.py`, `backend/db/database.py`, связанные маршруты в `backend/app.py`.

В коде присутствует FormGrab, который принимает и сохраняет введённые значения полей формы, а также Instagram Bruter, который запускает перебор паролей, использует wordlist/proxy и сохраняет найденные пары логин/пароль.

**Риск:** функциональность может использоваться для фишинга, сбора паролей и несанкционированного доступа к аккаунтам. Отдельные API для просмотра захватов и найденных паролей дополнительно создают риск раскрытия данных.

**Исправление:** не развивать эти функции. Для безопасной версии удалить/отключить сбор паролей, перебор, хранение найденных паролей, wordlist/proxy и соответствующие API. Для учебной демонстрации формы использовать только локальные фиктивные данные, явно обозначенную тестовую страницу и не сохранять секретные поля.

### HIGH — GrabCam имеет широкую поверхность сбора данных и удалённого доступа

**Файлы:** `backend/tools/tool_grabcam.py`, `backend/app.py`, `tools/grabcam/`.

В реализации присутствуют туннели Serveo/localhost.run/Cloudflare, генерация публичной ссылки, а также API для выдачи фото, экрана, аудио, геоданных, опций и ZIP-экспорта. В настройках по умолчанию в API указаны включённые camera, geo и form.

**Риск:** удалённый доступ к данным и сбор разных типов медиа/локации могут происходить вне понятного пользователю сценария согласия; при отсутствии авторизации сохранённые материалы могут быть раскрыты.

**Исправление с учётом требований проекта:** камера запускается только после отдельного явного действия пользователя и штатного разрешения браузера; геолокация — только после отдельного согласия. Не реализовывать скрытую съёмку, периодический автоматический сбор, доступ к галерее, микрофону или экрану, а также сбор паролей. Удалённые туннели должны быть выключены по умолчанию; локальная демонстрация должна быть очевидной и контролируемой пользователем.

### HIGH — хранение истории может сохранять чувствительные параметры и результаты

**Файл:** `backend/db/database.py`.

`save_run` сериализует параметры и результаты инструмента в таблицу `runs` без видимой фильтрации чувствительных значений. История доступна через API.

**Риск:** токены, персональные данные, URL с секретами и результаты расследований могут оставаться в SQLite и быть доступны через API истории.

**Исправление:** определить схему редактирования/маскирования секретов до сохранения, ограничить срок хранения, добавить явное удаление и контроль доступа. Не записывать пароли, API-ключи, содержимое приватных форм и необязательные персональные данные.

### HIGH — глобальный CORS

**Файл:** `backend/app.py`.

Используется `CORS(app)` без видимого ограничения origin.

**Риск:** широкая политика повышает вероятность нежелательных cross-origin обращений. Сам по себе CORS не даёт злоумышленнику доступ без других условий, но не должен оставаться глобальным разрешением.

**Исправление:** отключить CORS, если фронтенд и API обслуживаются одним origin; иначе разрешить только конкретные доверенные origin и нужные методы/заголовки.

### MEDIUM — в репозитории не обнаружен собственный набор тестов приложения

В корне не обнаружены отдельные тесты Flask-приложения; найденные тесты относятся к вложенным сторонним инструментам.

**Риск:** регрессии маршрутов, сериализации, запуска инструментов и поведения интерфейса могут не обнаруживаться автоматически.

**Исправление:** добавить pytest-набор для конфигурации приложения, доступности публичных страниц, схем API, валидации входных данных, авторизации, запрета доступа к приватным файлам и безопасного поведения модулей.

### MEDIUM — большой монолитный Flask-файл

**Файл:** `backend/app.py` (около 1 500 строк).

Маршруты страниц, фото-обработки, история, инструменты, GrabCam, AI и настройки сосредоточены в одном модуле.

**Риск:** усложняются тестирование, разграничение доступа и сопровождение.

**Исправление:** после закрытия критических проблем разделить маршруты на Flask Blueprints по доменам: core, tools, history, settings, photo, ai. Не менять публичные URL без совместимых алиасов.

## Приоритетный план

1. **P0 — безопасный режим:** отключить опасные маршруты/модули сбора паролей; закрыть административные и чувствительные API; выключить debug; убрать открытый сетевой bind по умолчанию.
2. **P1 — приватность:** пересмотреть GrabCam по принципу явного согласия; удалить скрытый/периодический сбор и доступ к галерее, экрану, микрофону; ограничить доступ к медиа и истории.
3. **P1 — защита данных:** маскирование секретов, срок хранения, права доступа, безопасные настройки CORS и лимиты размера запросов.
4. **P2 — качество:** добавить тесты и статические проверки, зафиксировать зависимости, подготовить production-конфигурацию.
5. **P3 — архитектура и новые функции:** Blueprints, очередь задач, Case Manager, граф связей и отчёты — только после прохождения P0/P1.
